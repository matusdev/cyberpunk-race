# NIGHT CITY RUSH — Blender asset pipeline

All 3D models of the game are generated by Python scripts that run inside Blender 5.2 in background mode.
Every script is reproducible: run it again and the same `.glb` (and an editable `.blend`) comes out.
You can open any `.blend` from `blender/out/`, tweak it by hand and re-export with the same settings.

```
"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" -b --factory-startup -P blender/<script>.py
```

Outputs:

| what | where |
|---|---|
| game models (GLB, meshopt compressed) | `public/models/*.glb` |
| editable scenes | `blender/out/*.blend` |
| preview renders (for review) | `blender/previews/*.png` |

## Conventions (the game code relies on these — do not change without updating the game)

* **Units**: metres. Real-world scale.
* **Axes (in Blender)**: Z up. Vehicles and front-facing props face **-Y**. Left side of a vehicle is **+X**.
  The glTF exporter (Y-up) turns this into three.js: up = +Y, front = **+Z**, left = +X.
* **Origin**: on the ground (Z = 0) at the centre of the footprint. For cars: centre between the axles.
* **Export settings** (always):
  ```python
  bpy.ops.export_scene.gltf(filepath=..., export_format='GLB', export_apply=True, export_yup=True,
      export_extras=True, export_meshopt_compression_enable=True, export_materials='EXPORT',
      export_cameras=False, export_lights=False, use_selection=False)
  ```
  No Draco. Apply all modifiers (`export_apply=True`). Custom properties (`obj["radius"] = 0.34`) become glTF `extras`.
* **Materials**: Principled BSDF only (base colour, metallic, roughness, emission colour + strength, alpha).
  No procedural node trees in the exported result — anything procedural must be baked or drawn into a small image
  (≤ 512 px, PNG) first. Material **names are a contract** — the game finds them by exact name and may replace them
  with its own shaders (paint recolouring, emissive pulsing, animated screens).
* **Shading**: smooth by angle (`bpy.ops.object.shade_smooth_by_angle(angle=radians(30..40))`) or explicit sharp edges.
  Mark sharp creases so lights/panels read crisply.
* **Budgets** are triangles after modifiers. Keep them — the game also runs on phones.
* **No external downloads.** Everything is modelled by the script.

## Files and object names

### `cars.glb`-family — player / racer cars (one file per car: `car_<id>.glb`)

Ids: `mizu`, `vektor`, `brutus`, `kaiju`.

```
car_<id>                (empty, origin)
├─ body                 (mesh or several meshes named body*, always visible)
├─ kit_0                (empty) stock bumpers/skirts as children
├─ kit_1                (empty) aggressive body kit: splitter, canards, wide skirts, diffuser
├─ spoiler_0            (empty, no children = no spoiler)  — or a tiny lip
├─ spoiler_1            (empty) ducktail / medium spoiler
├─ spoiler_2            (empty) big GT wing
├─ wheel_FL / wheel_FR / wheel_RL / wheel_RR   (empties at wheel centres; extras: radius, width)
├─ exhaust_0 … exhaust_N   (empties at the exhaust tips, pointing backwards; for nitro flames)
├─ headlight_L / headlight_R / taillight_L / taillight_R   (empties at light centres)
└─ cam_hood             (empty where a hood camera sits)
```

Materials: `Paint` (main paint, game recolours), `Carbon` (dark trims / carbon), `Chrome`, `Glass`, `Interior`,
`Headlight` (emissive white-cyan), `Taillight` (emissive red), `Accent` (emissive neon strips, game recolours),
`Grille`, `Rubber`. Wheels are NOT part of the car — the game mounts `wheels.glb` parts at the wheel empties.
Wheel arches must clear a wheel of the given radius/width with ~3 cm to spare.
Budget: ≤ 35k triangles for the whole file (one kit and one spoiler are visible at a time).

### `wheels.glb`

Centred on the origin, axle along **X**, outer face towards **+X** (the game mirrors for the right side).
`tire` (radius 0.34, width 0.25), `rim_0` … `rim_4` (fit inside the tire, rim radius ≈ 0.235),
`brake_disc` (spins with the wheel), `caliper` (does not spin, sits at the top-rear of the disc).
Materials: `Rubber`, `Rim` (game recolours), `RimAccent` (emissive), `BrakeDisc`, `Caliper`.
Budget: tire ≤ 1.5k, each rim ≤ 2.5k triangles.

### `traffic.glb` — background traffic (instanced by the game)

`tr_sedan`, `tr_compact`, `tr_taxi`, `tr_van`, `tr_pickup`, `tr_truck`, `tr_bus`.
Each one object, wheels modelled into the mesh. Materials (max 4 per vehicle): `Paint` (white base colour, the game
tints per instance), `Glass`, `Trim`, `Lights` (emissive, use vertex colours: white-yellow headlights, red tail lights).
Budget: ≤ 3k triangles (truck/bus ≤ 4.5k).

### `props.glb` — street furniture (instanced by the game)

Each prop is one object (or one parent empty with meshes) named exactly as below, origin at its base.
Front side faces **-Y**.

`lamp_street`, `lamp_old`, `traffic_light`, `barrier_jersey` (2 m long), `rail_guard` (4 m), `fence_park` (3 m),
`bollard`, `cone`, `barrel`, `crate`, `crate_stack`, `pallet`, `dumpster`, `trash_bin`, `vending_machine`,
`bench`, `hydrant`, `ac_unit`, `steam_vent`, `tree_park`, `tree_sakura`, `bush`, `market_stall`, `food_cart`,
`lantern_string` (8 m), `sign_frame` (with a `Screen` face), `billboard` (big, with a `Screen` face),
`holo_projector`, `container` (12 m, `Paint` material for recolouring), `antenna`, `water_tank`, `pipe_bundle`,
`satellite_dish`.

`Screen` material: emissive, its face UVs span 0..1 — the game puts animated ads / neon text there.
Budget: small props ≤ 500, medium ≤ 1.5k, large ≤ 4k triangles.

### `arch.glb` — architecture pieces / landmarks

`tunnel_frame` (neon portal frame for a 18 m wide, 9 m high tunnel, 0.6 m deep, `Accent` emissive strips),
`tunnel_portal` (big concrete megabuilding entrance for the same opening),
`hw_pillar` (elevated highway pillar, 1 m tall unit, the game scales it vertically — keep the cap separate: `hw_pillar_cap`),
`gantry` (sign gantry over a 20 m road, two `Screen` panels), `tower_crown_a`, `tower_crown_b`, `tower_crown_c`
(skyscraper roof tops for a 30×30 m footprint), `roof_japanese` (pagoda roof for 20×20 m), `awning` (market awning 6 m),
`crane_port` (large port crane), `kiosk`, `bridge_truss`.
Budget: ≤ 6k triangles each (crane ≤ 10k).

## Scripts and what the game reads from the files

| script | output | rebuild |
|---|---|---|
| `cars.py` (+ `cars_<id>.py`, `wheels.py`, `lib_cars.py`) | `car_*.glb`, `wheels.glb` | `blender -b --factory-startup -P blender/cars.py` (`-- mizu kaiju`, `--no-preview`, `--quick`) |
| `traffic.py`, `props.py` (+ `lib_props.py`) | `traffic.glb`, `props.glb` | `blender -b --factory-startup -P blender/props.py` (same for traffic) |
| `arch.py` (+ `lib_arch.py`) | `arch.glb` | `blender -b --factory-startup -P blender/arch.py` (`-- --only a,b`, `-- --verify`) |
| `verify_cars.py`, `verify_traffic_props.py` | — | re-import checks: names, materials, budgets |

Details the game depends on (beyond the contract above):

* **Car empties**: `headlight_*` keep identity rotation; `taillight_*`, `exhaust_*` and `cam_hood` are rotated 180°.
  The game only uses their positions. Wheel sizes can differ front/rear — each `wheel_*` carries its own `radius`/`width`.
* **Car glass** is alpha-blended; **Interior** is double-sided; the body underside is open (not visible in game).
* **Traffic** carries `kind`, `length`, `width`, `height` extras — the game sizes the collision boxes from them.
  `Lights` is white emissive with the real colours in vertex colours.
* **Props** may carry `light_points` (three.js local space) — the game puts glow halos there and, for street lamps,
  scales the pole so its light point matches the road lighting. `steam_points`, `holo_origin`/`holo_height` are reserved.
  `lamp_street` reaches 3.5 m towards its front; `lantern_string` has its own posts at ±4 m (the game stretches it across
  the street); the container's length runs along X.
* **Architecture**: `tunnel_portal` has `front_offset = 10` (its entrance face is 10 m in front of the origin);
  `hw_pillar_cap` has `pillar_top_z = -3.7` (where the scaled `hw_pillar` meets it); `tunnel_frame` has
  `opening_w`/`opening_h`.
* Materials named `Screen` are replaced in game by an animated ad atlas (UVs 0..1 across the face).

After regenerating a GLB just reload the game — models are loaded at runtime from `public/models/`.

# V2 assets (redesign after the reference art)

Everything above still applies (axes, origins, export settings, material-name contract). V2 raises the quality bar:
reference = dark rain-soaked Night City at night, glossy black supercars with full-width red light bars, dense
skyscrapers with vertical holo billboards, elevated ring roads, neon chevron signs, flying AVs. Think Cyberpunk 2077.

**Quality loop is mandatory**: render previews in a night setup, look at them with the Read tool, compare against
reference photos you download, iterate. Do not stop at the first version.

## Textures (allowed in V2)

* One texture atlas per asset family is allowed: ≤ 1024 px (cars, traffic, garage) / ≤ 2048 px (city kit), PNG or JPG.
* Use them for detail that geometry can't carry cheaply: grilles, vents, panel lines, decals, lettering, license plates,
  light patterns (emissive maps), dirt/grime.
* Never more than ~4 MB of images per GLB.

## Hero cars — `car_<id>.glb`, ids: `turbo`, `caliburn`, `shion`, `type66`

Faithful fan recreations of Cyberpunk 2077 cars (hobby, non-commercial): Quadra Turbo-R V-Tech (`turbo`),
Rayfield Caliburn (`caliburn`), Mizutani Shion (`shion`), Quadra Type-66 (`type66`). Same node/material contract as V1
(`body`, `kit_0/1`, `spoiler_0/1/2`, wheel/exhaust/light empties with extras, `cam_hood`), plus:

* Extra materials allowed: `Decal` (alpha-tested decals: badges, plate — uses the atlas), `Lightbar` is NOT a new name:
  the full-width tail bar uses `Taillight` (the game brightens it when braking); daytime running lights use `Headlight`.
* `Paint` stays the recolourable main paint; a second paint area (two-tone roof/hood) may use `Carbon` or `Chrome`.
* Budget: LOD0 ≤ 60k triangles for the whole file. Also export **`body_lod1`**: one merged mesh (body + kit_0, no spoiler,
  no wheels) ≤ 8k triangles, child of the root, hidden-by-name — the game shows it for distant cars.
* Wheels: still mounted by the game from `wheels.glb`; you may add/replace rims there (`rim_0`…`rim_7`), keeping
  `tire`, `brake_disc`, `caliper` names. Each car may set the extra `rim_default` (int) on its root.
* Each car carries extras on the root: `display_name` (e.g. "TURBO-R V-TECH"), `maker` (e.g. "QUADRA").

## Traffic — `traffic.glb`

Cyberpunk 2077 civilian traffic: `tr_hella` (Archer Hella sedan), `tr_maimai` (Makigai MaiMai micro car),
`tr_delamain` (Delamain Excalibur cab), `tr_colby` (Thorton Colby pickup), `tr_supron` (Mahir Supron SUV/van),
`tr_zeya` (Kaukaz Zeya truck), `tr_cortes` (Villefort Cortes sedan). Same material contract as V1 (`Paint`, `Glass`,
`Trim`, `Lights` + one shared atlas allowed). ≤ 5k triangles each. Extras `kind`, `length`, `width`, `height`.
Plus **`av.glb`** with `av_flyer` (a flying AV like the NCPD / Arasaka AVs, ≤ 6k tris, with `Lights`/`Accent`
emissive and thruster glow points as `light_points` extras).

## City kit — `city.glb`

* `tower_a` … `tower_h`: skyscrapers 60–260 m tall, footprints 25–60 m, origin at ground centre, strong silhouettes
  (setbacks, fins, balconies, crowns, antennas, sky-bridges stubs). **Facade UVs in metres**: material `Facade`
  (and `FacadeB`) with UV u = horizontal metres along the face, v = metres above the base — the game draws the windows
  procedurally from those UVs. Other materials: `Concrete`, `MetalDark`, `Glass`, `Accent` (emissive edges, recoloured
  by the game), `Screen` (vertical holo billboards, UV 0..1 per screen), `WarnLight`.
* `megablock_a`, `megablock_b`: Night City megabuildings (stacked residential modules, terraces, neon), same materials.
* `corpo_tower`: the Arasaka-like landmark — cylindrical/bevelled tower ~300 m with a huge glowing ring and a
  `Logo` material face (UV 0..1) for the corp logo.
* `ring_road`: decorative elevated circular road (radius ~140 m, 270° arc) on pillars with neon underlights.
* `chevron_sign`: neon curve-warning sign »» on a post/barrier (≈ 2.4 × 1.2 m panel), `Screen` UV 0..1 or emissive geometry.
* `barrier_led`: 4 m concrete jersey barrier with a continuous LED strip (`Accent`).
* `holo_frame`: giant vertical billboard frame for building faces (≈ 12 × 40 m) with a `Screen` face.
* `light_arch`: neon arch / gate spanning a 20 m road (sponsor gate), `Screen` panel + `Accent` ring.

## Garage — `garage.glb`

A drive-through Night City tuning garage (its own scene in the game): 30 m wide × 38 m deep × 9 m high hall, steel trusses,
ceiling light bars (`LampLight`), side bays with car lifts, tool carts, workbenches, wall monitors (`Screen`), graffiti mural
(`Mural`, UV 0..1 across the wrapped wall), neon logo sign (`Logo`, UV 0..1), tyre stacks, cables, wet concrete floor (`Floor`).
Script: `garage.py` + `lib_garage.py` (`-- --quick`, `--only a,b`, `--no-preview`, `--verify`). Budget ≤ 120k triangles,
textures ≤ 1024 px, ≤ 4 MB of images, emissive strength ≤ 3.

* **Two open 14 × 6 m roll-up doors** on the x = 0 axis: FRONT at three.js +Z (z = 18.15), BACK at −Z (z = −20.15). The car
  arrives through the back door, stops on the origin facing +Z, and leaves through the front door. |x| ≤ 5 m is a clear
  driving aisle door to door; the 6 × 10 m box around the origin is clear.
* A **12 m paved apron** (`Floor`, kerbs, drain, `EXIT` / `ENTRY` stencils) lies outside each door; the game shows a city
  backdrop image beyond it. The exterior shell (facades, door portals with LED strips, neon signs, roof kit) also exists.
* **`Floor` UVs are metric**: in three.js the uv attribute is exactly (x, z) in metres (hall + aprons). The material's own
  textures repeat every 5 m through `KHR_texture_transform` (scale 0.2), so the game can lay its own wet-floor shader on top.
* `Countdown`: emissive screen above the front door inside (6 × 1.6 m, UV 0..1) - the game draws COUNTDOWN 3 / 2 / 1 / GO.
* `Grime`: alpha-blended dirt decals (oil, tyre tracks, leaks, rust runs, scuffs) - UVs into a small atlas, keep as is.
* Empties: `bay_L`, `bay_R` (lift tops, extras `lift_height`), `cam_main`, `cam_side`, `cam_back` (camera empties: local −Z
  looks at the target, extras `target`), `door_front`, `door_back` (opening centre at floor level, extras `size`),
  `car_spot` (origin), `lights` (extras `light_points` / `light_colors` inside, `ext_light_points` / `ext_light_colors`
  outside). Root extras: `door_front_center`, `door_back_center`, `door_size`, `door_center` (legacy, front door mid-height),
  `clear_zone`, `aisle_half_width`, `apron_length`, `interior_size`, `exterior_bounds`, `mural_object`, `logo_object`, `countdown_object`.

## Street props V2 — `props.glb` (`props2.py` + `lib_props2.py`)

```
blender -b --factory-startup -P blender/props2.py              # build, export, previews, verify
        -- --quick | --only a,b[,street] | --no-preview | --verify
```
`--only` builds / previews just those props and writes no GLB (`street` = all props + lineups + street scene);
`--verify` re-imports `public/models/props.glb` in a fresh process (names, budgets, ground, Screen UVs, emission ≤ 3,
Leaves = MASK + double sided, texture sizes ≤ 1024, light points, file ≤ 4 MB). A full build runs the verify itself.
Same names / origins / orientation / footprints (±15 %, the build prints the deviation from the V1 object) and
`light_points` as V1; the props not rebuilt in V2 come from the V1 builders in `props.py` with the V2 materials.

* **New names** (not placed by the game yet): `tree_palm` (~10 m), `tree_park_b` (oak, ~7 × 7 × 5.7 m), `hedge` (2 m along X),
  `market_stall_b` (produce, tarp), `market_stall_c` (yakitori shack), `bench_b`, `trash_bin_b`, `recycle_bins`,
  `fence_metal` / `fence_chain` / `fence_construction` (3 m along X), `planter`, `bus_stop` (4 m, double-sided `Screen`
  ad lightbox), `newspaper_box`, `bike_rack` (with a bike), `street_sign`, `bollard_led`, `phone_booth` (`Screen`
  terminal), `parking_meter`. Market props also carry `steam_points`.
* **Materials** (emission ≤ 3; the game maps `LampLight`/`Lantern`/`Accent` to unlit colour × vertex colour, so their
  colours come from COLOR_0): `Leaves` (alpha clip 0.4, double sided, atlas × vertex colour — foliage cards have
  custom normals blended towards the crown volume), `Bark` (atlas + normal map), `MetalPaint` (worn-paint photo ×
  vertex colour), `MetalDark` (same photo × dark factor), `Wood`, `Concrete` (photo tiles, box-projected UVs in metres),
  `Market` + `Signage` (one generated 1024 atlas: goods / emissive kanji boards), `Decal` + `SignageB` (street graphics
  atlas), `Fence` (chain-link alpha tile, UVs repeat), `GlassClear` (alpha blend 0.22), plus the V1 names.
* **Textures**: CC0 sources in `blender/cc0/` (ambientCG / Poly Haven, listed in `public/CREDITS.md`); the generated
  atlases are written to `blender/out/props2_tex/` for inspection. Previews: `previews/v2_props_*.png`.
